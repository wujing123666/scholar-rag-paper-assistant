# ScholarRAG 评测记录与口径

本页整理 2026-09-28 至 2026-09-29 的本地实验，文档整理日期为 2026-10-15。用于说明配置、结果和已知问题；没有将历史结果当作本次重新测得的成绩。

原始 JSON 报告、答案与引用正文留在被 Git 忽略的本地目录。公开内容包括聚合结果、脱敏逐题计数与[复现入口](reproduce.md)，不包含私有 PDF 全文、API Key 或个人阅读记录。

## 1. 多方面正文检索对照

数据为 30 道模型生成的开发题，标注 72 个可覆盖方面；答案页经过 PDF 原页核对。对照使用相同的重排配置和 Top-7 预算，比较整句查询与方面查询，属于开发实验，不是未见用户盲测。

| 指标 | 整句检索 + FastEmbed | 方面检索 + FastEmbed |
|---|---:|---:|
| Coverage@7 | 81.94% | 90.28% |
| 所有方面均覆盖的问题 | 21/30 | 24/30 |
| Page Recall@5 | 90.00% | 100.00% |
| Page Recall@1 | 66.67% | 63.33% |

Coverage@7 指检索证据覆盖的标注方面数占可覆盖方面数的比例。该对照说明方面检索改善这批问题的整体覆盖；Page Recall@1 略降，因此不能表述为所有指标均提升。此实验早于后续 676 篇扩库与方面独立论文路由，不将不同阶段的结果合并成一个 A/B 实验。

原始计数为 59/72 与 65/72，差值为 8.33 个百分点；从已舍入的两端百分比相减会得到 8.34，公开复算以原始计数为准。

实现：[query_split.py](../../src/paper_assistant/query_split.py)、[facet_query.py](../../src/paper_assistant/facet_query.py)。

## 2. 固定答案的评审成本回放

使用已冻结的 14 个答案、169 条 Claim 及其证据，比较全量双审与高风险分流，避免重新生成答案带来的差异。

| 设置 | 评审 Token | 说明 |
|---|---:|---|
| 全量双审基线 | 82,148 | 原冻结答案运行中的评审用量 |
| 风险分流冷缓存 | 72,081 | 第二评审检查 96 条高风险 Claim；Token 降低 12.25% |
| 相同输入热缓存 | 0 | 265 个模型—Claim 判定全部复用 |

冷缓存回放存在 1 次缓存命中，264 次未命中；表中“冷缓存”是该轮实验的命名，并非严格保证每次判分都无缓存。两轮的 Claim 保留数相同，但数据未覆盖所有错误结论类型，不能据此证明分流不会漏判。热缓存耗时由 37.945 秒降至 0.060 秒，只适用于完全相同的固定输入，不能推断线上命中率。

实现：[claim_safety.py](../../src/paper_assistant/claim_safety.py)、[缓存](../../src/paper_assistant/claim_judgement_cache.py)。

## 3. 规模库与突发请求验收

语料使用独立的 `data/papers/corpus_iot_1000/` 目录与 `data/db/chroma_iot_scale/` 数据库，通过同一 PaperAssistantService 执行。目录名称中的“1000”为采集目标，实际入库为 676 篇，不把目标数量写成完成数量。

| 项目 | 结果 |
|---|---|
| 论文 / 正文 Chunk | 676 / 53,578 |
| Embedding | Qwen text-embedding-v4，1024 维 |
| 论文 / 正文重排 | BAAI/bge-reranker-base，经 FastEmbed/ONNX 执行 |
| 并发提交 | 20 个不同问法，来自 10 个主题 |
| 执行槽 / 等待容量 / 等待预算 | 3 / 20 / 180 秒 |
| 完成 / 失败 / 队列超时 | 20 / 0 / 0 |
| 检索或重排降级请求 | 0 |
| 总墙钟时间 | 134.25 秒 |
| P95 总响应时间，含排队 | 127.579 秒 |
| 最长等待 | 124.829 秒 |
| 峰值 RSS | 5573.07 MiB，约 5.44 GiB |

该并发阶段关闭 Claim 语义评审，包含实际检索与 LLM 生成。它验证有界队列能够承接本轮突发请求，不代表 20 个问答在同一时刻执行、不代表低延迟，也不代表双评审开启时的吞吐。搜索-only 暖缓存时间不能混入完整问答延迟。

2026-10-15 修复了共享重排器的惰性推理锁：FastEmbed 返回生成器，现已在锁内完成迭代。该修复使原设计的串行推理实际生效，可能改变资源占用和延迟；上表仍是修复前的历史记录，新版本部署应重新验收容量。

索引同步另有无变更复用检查；索引首次构建的进度文件包含新增向量，不能拿它宣称首次构建零调用。重启复用能力由内容哈希、模型身份、维度及分块配置共同约束。

复现入口：[容量验收脚本](../../scripts/accept_iot_scale.py)、[检索基准脚本](../../scripts/benchmark_iot_retrieval.py)。运行前使用自己的语料与配置，通过脚本 `--help` 确认路径；完整验收会产生模型调用费用。

## 4. 扩展路由评测发现的问题

冻结 Paper Cross-Encoder 门槛 2.5 后，追加 100 道元数据派生的弱线索正例与 40 道系统编写的库外负例：

- 已知题通过 63/100，说明门控存在明显误拒。
- 库外题拒绝 40/40，只表示这一批负例的结果。
- 进一步使用 20 道自然中文问题，语义找回成功 17/20；这些问题仍由系统改写，不是用户独立盲测。

这批实验不能当作线上准确率。它揭示短问句、中英混合表达与绝对 logit 门槛的校准问题，因此根 README 没有沿用早期小开发集的 97.4% 作为系统整体准确率。后续应在新的冻结留出集上比较门控或多语言重排方案，不能边看结果边修改测试题。

## 5. 生成内容与跨模型审计

沿用 20 道自然中文问题，执行 Qwen/Hybrid、论文门控、正文重排、DeepSeek 生成和风险分流共识核验，并关闭 Claim 缓存：

- 17 题生成答案、3 题安全拒答、0 运行错误；拒答与前述路由问题一致。
- 最终答案包含 132 条 Claim。独立 Qwen 筛查判为 130 条 supported、1 条 partial、1 条 unsupported。
- 引用结构检查通过，独立模型完全支持率为 98.48%。结构有效不等于语义正确。

两条分歧随后对照 PDF 原页，记录为评审误判；另以固定种子抽查 10 条共同支持项，记录为原文支持。该复核由 AI 辅助代理完成，没有独立领域专家逐条标注全部 Claim，因此不能把它称为专家人工金标准，也不能把“本轮未确认幻觉”推广成系统幻觉率为零。

实现：[答案评测](../../src/paper_assistant/answer_evaluation.py)、[冻结评审对比](../../src/paper_assistant/judge_comparison.py)。生成模型、运行时核验和离线审计承担不同角色；双模型一致只是一项检查信号。

## 6. 结果使用原则

- 同一对照中的配置、语料、问题和统计口径需固定；跨阶段的不同实验分开描述。
- 开发集、系统生成题、元数据派生题与用户独立盲测明确区分。
- 正文引用、答案通过率、事实覆盖、模型支撑率、拒答表现与响应时间分别统计。
- 代码支持某功能、功能在单题运行通过、功能在批量实验表现良好，是不同层次的证据。
- 完整重跑历史实验需要相应私有语料、报告与模型服务；公开脱敏记录支持统计复算，公开合成 PDF 包支持独立的示例检索与问答，两者不能冒充历史实验重跑。
