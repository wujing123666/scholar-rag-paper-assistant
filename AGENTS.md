# Repository working instructions

## Project memory is mandatory

After completing any meaningful implementation, bug fix, evaluation, data preparation, GitHub PR, or architectural decision, append a dated entry to `docs/PROJECT_MEMORY.md` in the same change.

Each new entry must record:

1. the goal and reason for the work;
2. the observed problem or starting state;
3. the implementation and important files;
4. key technical decisions and rejected shortcuts;
5. commands or workflow used to verify the result;
6. exact test or evaluation results, including known failures and limitations;
7. Git branch, commit, and PR information when available;
8. a concise interview-ready explanation;
9. the next recommended step.

Append new entries under the work log without rewriting or deleting earlier history. Update the “Current state” and “Next roadmap” sections when the project state changes. Never report generated or same-source evaluation data as an unbiased final metric.
